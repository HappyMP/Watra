# Phase 10 — Email Transactional Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** WATRA-branded transactional emails (registration, verification, password reset, booking confirmation, booking cancellation) sent asynchronously via Symfony Messenger + Doctrine transport.

**Architecture:** Override `@SyliusCoreBundle/Email/layout.html.twig` for global WATRA branding. Override the order confirmation content block for event details. Add a new `booking_cancelled` email type via `sylius_mailer.yaml` + an EventSubscriber on `workflow.sylius_order.completed.cancel`. All emails go async via `Symfony\Component\Mailer\Messenger\SendEmailMessage` routed to a `doctrine://default` Messenger transport.

**Tech Stack:** Sylius MailerBundle (`SenderInterface`), Symfony Mailer, Symfony Messenger, Doctrine transport, Symfony Workflow events, Twig inline-CSS email templates.

- [ ] **Step 3: Create BookingCancelledEmailSubscriber**

Create `src/EventSubscriber/BookingCancelledEmailSubscriber.php`:

```php
<?php

declare(strict_types=1);

namespace App\EventSubscriber;

use Sylius\Component\Core\Model\OrderInterface;
use Sylius\Component\Mailer\Sender\SenderInterface;
use Symfony\Component\EventDispatcher\EventSubscriberInterface;
use Symfony\Component\Workflow\Event\CompletedEvent;

final class BookingCancelledEmailSubscriber implements EventSubscriberInterface
{
    public function __construct(
        private readonly SenderInterface $emailSender,
    ) {}

    public static function getSubscribedEvents(): array
    {
        return [
            'workflow.sylius_order.completed.cancel' => 'onOrderCancelled',
        ];
    }

    public function onOrderCancelled(CompletedEvent $event): void
    {
        /** @var OrderInterface $order */
        $order = $event->getSubject();

        $customer = $order->getCustomer();
        if ($customer === null) {
            return;
        }

        $email = $customer->getEmail();
        if (empty($email)) {
            return;
        }

        $this->emailSender->send(
            'booking_cancelled',
            [$email],
            [
                'order'      => $order,
                'channel'    => $order->getChannel(),
                'localeCode' => $order->getLocaleCode() ?? 'pl_PL',
            ],
        );
    }
}
```

## Task 5: Messenger Async Transport

**Files:**
- Modify: `config/packages/messenger.yaml`

Sylius uses `Symfony\Component\Mailer\MailerInterface` via `SymfonyMailerAdapter`. Symfony Mailer internally dispatches `Symfony\Component\Mailer\Messenger\SendEmailMessage` to the Messenger bus when available. Routing this class to `async` makes ALL Sylius emails async. Rendering (Twig) still happens synchronously at call time; only SMTP sending is deferred.

- [ ] **Step 1: Update messenger.yaml**

Replace the full content of `config/packages/messenger.yaml` with:

```yaml
framework:
    messenger:
        transports:
            async: 'doctrine://default'
            sync: 'sync://'

        routing:
            'Symfony\Component\Mailer\Messenger\SendEmailMessage': async
```

- [ ] **Step 2: Verify Messenger config**

```bash
sudo docker compose -f compose.yaml exec php bin/console debug:config framework messenger 2>&1 | grep -A 10 "transports:"
```

Expected: shows `async: doctrine://default` and routing for `SendEmailMessage`.

- [ ] **Step 3: Verify Doctrine transport table is created (Messenger needs `messenger_messages` table)**

```bash
sudo docker compose -f compose.yaml exec php bin/console messenger:setup-transports 2>&1
```

Expected: `[OK] The "async" transport was set up successfully.` (creates `messenger_messages` table in Postgres).

- [ ] **Step 4: Commit**

